# 大螢幕要放哪些內容（新人自己選）

新人想要的不只一種（2026-10-03）：逐字歌詞的 MV、只要音樂和祝福、不要賓客留言、放照片和註解……
所以不做成幾種固定的「模式」，而是**幾樣可以各自開關的內容**，後台再給幾個常見的組合一鍵套用。

## 設定

存在婚禮的設定 `wall_content`（JSON，`backend/app/stage.py` 的 `wall_content()` 讀，缺的欄位用預設值補）：

| 欄位 | 預設 | 意思 |
|---|---|---|
| `lyrics` | true | 逐字歌詞。關掉時引擎給每個窗格空的歌詞（照純音樂畫），歌單也不用對歌詞 |
| `messages` | true | 賓客祝福留言。關掉時：沒有 QR、沒有邀請卡、`/wish` 跟沒開放一樣（送出 403）；feed 只給新人自己寫的話 |
| `photos` | false | 照片＋註解（婚紗照頁的照片，註解就是照片的「說明」）。預設關著：新人在後台自己打開才放（版面的紙偶角色仍然只用畫的，見 ENGINE.md「紙偶角色」） |
| `captions` | true | 照片下面放不放註解 |
| `albums` | [] | 舊欄位（要上大螢幕的相簿，空的 = 全部）：改成每本相簿自己的設定後不再用，第一次改相簿設定時自動轉過去 |
| `mix` | even | 照片與一般窗格的比例：`all`（每一格都是照片）、`photos`（2:1）、`even`（1:1）、`messages`（1:2） |

- API：`GET/PUT /api/planner/wall/content`（`wall`、`wall_setup` 兩把鑰匙都能改：婚禮前新人選，當天幫手用手機切）。
- 後台：「大螢幕」的「內容」分頁（`WallContent.jsx`）；「遙控」分頁有「畫面放什麼」一鍵切組合；留言、歌單分頁在內容關掉時上方有提醒（`ContentOffNote`）。
- 常見的組合（`PRESETS`）：歌詞 MV、祝福牆（不放歌詞）、照片回顧（只放照片）、全都要（照片上也唱歌詞、放祝福）。

## 大螢幕怎麼照著排（`director.ts`、`engine.ts`、`main.ts`）

- feed 帶 `content` 與 `photos_rev`；`main.ts` 的 `applyContent()` 套用，內容變了就把還沒開始的窗格重排（幾秒內看得到）。
- 照片窗格與一般窗格照 `mix` 輪流（`all` 或歌詞、留言都關著時每一格都是照片）。**照片窗格也是 MV**：新人開了歌詞就照樣跟唱、開了留言就照樣放祝福，
  所以新人選「全都要」時照片上看得到歌詞與祝福，不是三樣輪流各放各的。
- 照片窗格只排照片版面（版面檔 `spec.photo: true`），`params.photo` 是 `photos.ts` 的 `PhotoRef`。主字（`director.ts` 的 `photoHero`）：
  新人不放留言 → 註解；有新留言在排隊 → 新留言插隊（不管排到照片窗格還是一般窗格，賓客都在十幾秒內看到）；沒有註解的照片 → 一則舊留言；
  有註解的照片 → 一輪註解、一輪留言（照片 id 錯開奇偶，第一輪就有一半照片放祝福）。歌詞在主字下面小一號跟唱；沒有主字時歌詞自己當主字。
  照片版面的畫法見 ENGINE.md「照片版面」（字用 `_photo.ts` 的 `PhotoText`）。
- 依照片挑版面：照片清單帶長寬、亮度、色調、焦點（`files` 表的 `img_w`、`img_h`、`lum`、`tone`、`focus_x`、`focus_y`；
  上傳時算一次，之前上傳的第一次要清單時補算）。照片池 `peek()` 看接下來幾張的種類與亮度，導演用 `photoFit()` 給適合的版面加權：
  版面 `spec.prefers` 寫的種類（橫、直、方、很小）越符合越優先，暗的照片配亮版面、很亮的配暗版面；一次放好幾張的版面要照片池準備好的張數夠才排。
- 焦點：「婚紗照」頁照片的鉛筆 → 點一下照片上最重要的地方（通常是臉），存成 0..1 的位置；可以清掉回到預設（中間偏上）。改了焦點照片版本號會變，大螢幕重抓清單。
  每個照片版面都往焦點推（臉越來越大、越來越靠近框的中間，`_photo.ts` 的 `focusCrop`），新人點了就看得出來。
- **每本相簿給誰看**（設定 `photo_albums`，`stage.album_flags`）：`guests` 賓客在婚禮網站的照片頁看得到、`wall` 放大螢幕，沒設定過的兩個都是開。
  照片頁同時放婚紗照與只想放大螢幕的生活照，所以賓客看不到的相簿，就算單張標了公開也不會出現（照片清單不列、照片網址 404）。
  照片頁每本相簿上方有兩個開關（`PUT /api/planner/photos/albums`，改 wall 要大螢幕的鑰匙）；上傳新相簿時要先選用途（網站＋大螢幕／只給賓客看／只放大螢幕），照片一上來就照設定。
  大螢幕「內容」分頁的相簿開關改的是同一份（`PUT /api/planner/wall/albums`）。
- 照片：`GET /api/planner/wall/photos`（清單＋所有相簿）、`/photos/{id}/image`（長邊 2048 的 JPEG，第一次要時才做，存在原檔旁邊 `wall_<檔名>.jpg`，刪照片時一起刪）。
  大螢幕開機後一張一張在背景下載、放 Cache Storage（會場網路斷了照樣有照片），還沒下載好的先跳過。

## 場合：當天流程每一段放什麼歌、什麼畫面

婚禮當天流程一段一段走（迎賓、新人進場、證婚致詞、用餐、二次進場、敬酒、送客），每一段要的音樂與畫面不一樣。
以前要幫手在手機上一首一首插播、再切「畫面放什麼」；現在新人先把每一段存成**場合**，當天在遙控按一下就整組換過去。
流程由新人自己決定，所以場合**全部由新人自己新增、改名、排順序、挑歌**，不寫死流程；「常見流程」只是範本（`wall_scenes.TEMPLATE`）。

### 一個場合有什麼（`wall_scenes` 表，`app/wall_scenes.py`）

| 欄位 | 空的時候 | 意思 |
|---|---|---|
| `name` | — | 遙控上按的名字（20 字內） |
| `song_ids` | 不換歌 | 這個場合播的歌（照順序）。**歌單關掉「要播」的歌，挑進場合照樣播**（進場曲只在進場時播）；沒挑歌的場合（致詞）接著播原本的歌 |
| `shuffle` | 照順序 | 隨機播放 |
| `content_json` | 跟「內容」分頁一樣 | 畫面放什麼（歌詞、留言、照片、照片比例）；註解與相簿照「內容」分頁 |
| `plates` | 照「版面」分頁 | 只用這幾個版面（挑了就算在「版面」分頁關掉也用）。只挑了一般版面時照片窗格照「版面」分頁的照片版面排，反過來也一樣 |
| `pace` | 照「版面」分頁 | 換版面的節奏 |
| `theme` | 每首歌自己的 | 配色 |
| `duck` | 不開 | 切過來時自動開講話模式（致詞、證婚、文定儀式），換到別的場合自動恢復 |
| `after_id` | 重複播 | 歌都播過一輪之後自動換到哪個場合（新人進場曲播完回到用餐） |

刪掉的歌、場合在輸出時拿掉（存的資料不動）；刪掉一個場合時，「播完之後換到它」的改成重複播，排好要換到它的取消。

### 現在是哪個場合（設定 `wall_scene`）

`{"id": 場合或 null, "seq": 切換編號, "next": {"id": …} 或 null}`。

- `POST /api/planner/wall/scenes/switch {id, when}`（當天操作的鑰匙）：`now` 馬上換（seq 加一，切到同一個也算，從第一首重播）、
  `end` 這首播完再換（記在 next）、`cancel` 取消排好的。`id = null` 是「不指定場合」（照整份歌單、「內容」分頁）。
- **feed 給的內容是合併過的**：`content`、`pace` 已經照現在的場合（`wall_scenes.effective_content`），另外帶 `scene`（歌、版面、配色、講話模式、播完之後）、
  `scene_seq`、`scene_next`、`scenes`（名字，大螢幕歌單面板的場合按鈕）。
- **賓客留言**：「內容」分頁或現在的場合有一個放留言，`/wish` 就收（`wall_scenes.messages_on`）。場合不放留言時照樣收（賓客可能寫到一半），
  換到放留言的場合就上螢幕；「內容」分頁不放、但這個場合放留言時，切到這個場合才開放。

### 大螢幕怎麼照著播（`main.ts` 的「場合」一段）

- `scene_seq` 變大就是有人切了：挑了歌的場合換成它的歌，現在這首 1.5 秒淡出後從第一首開始；沒挑歌的只換畫面與講話模式。
  比較早發出、比較晚回來的 feed（seq 比較小）不理。後台改了現在這個場合的歌：照新的清單接下去，不重新開始。
- 「這首播完再換」與「播完之後換到…」：**接收遙控的那台**在歌播完（或按下一首）時帶著它看到的場合與 seq 來換（`expect_from`、`expect_seq`），
  伺服器確認狀態沒變、要換的就是排好的那個才換，所以好幾台開著也只換一次，中間有人用手機切過、取消了也不會被蓋掉。換好了等 feed 帶新場合來（最多 5 秒）再播。
- 版面：導演的 `only`（`director.ts`）。只挑一兩個版面時照樣重複播它們，不會跑出沒挑的版面。
- 場合的隨機播放是後台設的：遙控在場合裡臨時切只算這一次，不記成那台電腦的預設。
- 版面預覽（`?plate=`）、開發、截圖模式不管場合。

### 後台

- 「大螢幕」→「場合」分頁（`WallScenes.jsx`）：新增、編輯（名字、歌與順序、播完之後、畫面、版面、節奏、配色、講話模式）、上下移、刪除；
  沒有場合時可以一次加入常見流程。
- 「遙控」分頁最上面的「場合」（`WallRemote.jsx`）：按了選「馬上換」或「這首播完換」；排著的可以「馬上換」或取消。
  「畫面放什麼」在現在的場合有自己的設定時改的是那個場合，沒有就改「內容」分頁。
- 大螢幕的歌單面板（L）也有場合按鈕，按兩下才換（投影畫面上誤觸一次不會換掉）。
- 測試：`backend/tests/test_wall_scenes.py`。

## 不放賓客留言時，留言的位置放什麼

189 個版面裡有 184 個在「沒有主打留言」時會畫「掃描右下角 QR code，把祝福寫上大螢幕」的邀請。不放留言就沒有 QR，那句話不能出現，
所以**不放賓客留言時，每個一般窗格都一定有主打的話**：feed 只給新人自己寫的話（留言分頁「新增」的，`source = couple`），
一句都沒有時給 `DEFAULT_COUPLE_LINES` 幾句預設的感謝詞（id 是負數）；導演在只剩一兩句時也照樣重複放，不讓版面落到邀請的畫法。
大螢幕把沒填名字的新人留言署名成新人的名字。

之後如果要做「完全沒有留言區、只剩歌詞」的畫面，得每個版面加一個「不畫邀請」的畫法（例如 `ctx.live` 帶 `wish: false`），一個一個改、一個一個截圖驗收。
